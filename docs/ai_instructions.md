# AI実装ルール：MorseCodeTestApp## 1. 共通設計原則- **UI/UX:** 添付の二分木レイアウトを厳守すること。- **データ駆動:** 遷移ロジックはハードコーディングせず、必ず `morse_tree.json` の構造に基づいて動的に制御すること。- **アーキテクチャへの干渉禁止:** 本ドキュメントでは振る舞いのみを規定し、特定のデザインパターン（MVVM, Clean Architecture等）の選択は開発者に委ねる。ただし、可読性とテスト容易性を確保すること。## 2. 入力判定ルール- **長短判定の閾値:**  - `SHORT_PRESS`: 200ms未満  - `LONG_PRESS`: 200ms以上- **リセット時間:**  - 最後の操作から `1500ms` 経過した場合、状態を `root` (アンテナ) に戻すこと。- **ビープ音:**  - ボタン押下開始（ACTION_DOWN）と同時に発音を開始し、指を離した（ACTION_UP）瞬間に停止させること。## 3. UI・アニメーション挙動- **点灯（Active状態）:**  - ボタンが押されている間、対応するノード（○または▭）を点灯（例：黄色 #FFFF00）させること。  - 点灯対象は「現在位置から、入力種別（短/長）によって特定される次ノード」とする。- **視認性:**  - 非アクティブなノードは透過度を下げるか、グレーアウト表示にすること。- **配置:**  - 画面最下部中央に、操作用メインボタンを配置すること。## 4. 移植性を考慮した実装ルール- **JSONパース:**  - `id` をキーとした Map 構造でデータを保持し、`dot_id` や `dash_id` を用いて O(1) で遷移先を参照できるように実装すること。- **リソース分離:**  - テキスト、カラーコード、判定閾値は、プログラム本体ではなく設定用定数またはリソースファイルから参照すること。## 5. 禁止事項- 要件にない画面（設定画面、履歴画面等）を勝手に追加しないこと。- 二分木以外のデータ構造（ただのリスト表示等）に変更しないこと。- 外部ライブラリを最小限にし、可能な限り標準APIで実装すること。
